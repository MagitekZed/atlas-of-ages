# Wave 0 notes for builders

Wave 0 implemented `docs/design/expansion-contracts.md` in `src/core` and the UI/render registries. Existing histories are unchanged (fingerprints identical). Read this before building: it lists where the code deviates from the contract text, practical notes, and gaps that specific packages must close.

## Gaps assigned to packages
- WP5 (genesis.js) and WP8 (worldtab.js, widgets.js) do not honour visibleIf yet (I did not touch them: not Wave 0 files). So at mythLevel 0, Genesis shows the Myth & Magic group: the mythLevel select (Legendary and Mythic can be chosen), magicStrength, monsterAbundance, divineIntervention, wildMagic, raceMix and fading. It also lists the 5 mythic presets (High Fantasy, Age of Dragons, Twilight of Magic, Elder Races, Legends) mixed in with the historical presets, though none of them does anything yet. The World tab shows a Myth & Magic group of live sliders, plus fortune, worldAges and banditry, which are inert until WP1 and WP2 land. The worldName param has no input field (paramControl has no 'text' type). WP5 must group the mythic presets by mode, add the Historical / Legendary / Mythic switch, keep Legendary disabled and filter with paramVisible. WP8 must filter the World tab the same way.
- WP8: worldtab.js still calls setParam(w, k, v) without {log: true}, so slider changes are not in world.interventions and undo/rewind replays would lose them (contracts §1, §11).
- WP8: src/ui/plate.js is a copy of atlas.js drawPlate, not an extraction. atlas.js still draws its own plate and should switch to drawAtlasPlate.
- WP8: app.select() still clears app.follow. The contract wants follow to survive a selection change and be cleared by userCamera. No key is bound to app.frameSelection (Z is WP8's). Nothing handles the app events chronicleScrollTo and timeTravel yet; atlasGoto is handled by atlas.js. Pair and entity tools are kept off the palette belt until WP8's pair flow and divine-acts sections exist. The palette rebuilds only on 'world' and 'toolsChanged', so a tool whose available(world) changes mid-run (awaken_magic) needs a toolsChanged emit.
- WP7 renderer stubs. setSelection({kind: 'civs', ids}) and setSelection({kind: 'box', …}) are accepted and stored but draw nothing. setToolPreview and setHighlights only store their input. getZoomInfo uses placeholder band thresholds. frameBox ignores phone-sheet insets. lodReady stays false. src:'tool' fx get priority 10 and no time scaling, but there is no off-screen pointer or fxPointer hit yet.
- WP4: war.js replaces army.flags right after createArmy. It must merge (Object.assign) so the flags.loss written by kernel damageArmy (created lazily on first damage) survives. All casualties should go through damageArmy.
- WP3: extVersion() is process-local and must never be folded into saved state (for example civ.mods), or --determinism fails.
- WP3 note from the fix above: civ effects have no kernel aggregate cache. If WP3 caches computeMods across days, it must judge effect liveness at a deterministic day (as settlementMods now does), not at cache-fill time, or save → load → continue will diverge.
- Deviations from the implementers that I accept (all documented in SPEC): the 'mods' ext point combines with concatOf (the contract leaves combine blank); RACE_KEYS is exported instead of RACES; addEffect drops the existing soonest-expiring effect and always keeps the new one; worldChecksum mixes 32-bit words and is not byte-wise FNV; replayTo takes extra options (from, sliceMs, signal, applyFinal); the chronicle prune keeps the 12-per-sid and 24-per-civ retention but falls back to imp ≥ 3 and the newest entries when still over the cap. The prune changes which imp-1 entries the UI keeps only in runs that pass 6,000 entries; sim state is unaffected.

## Kernel deviations (accepted)
- TOOL_GROUPS now lives in core/constants.js (the task asked for the change in constants.js) and core/tools.js re-exports it, so palette.js's import from tools.js still works.
- mythLevel/mythOn are defined in core/params.js, where the contract lists them, and re-exported from core/world.js.
- constants.js exports RACE_KEYS, not RACES, so it does not clash with WP5's published RACES from myth/index.js. RACE_META also has a 'plural'. BAND_KINDS.flags is an object ({sea, fly, mythic}). For beasts with no glyph in the contract table the glyph is the kind name; company uses 'banner'.
- addEffect cap: once 12 effects exist, the EXISTING effect that expires soonest is dropped (permanent ones count as never expiring; ties drop the oldest). The new effect is always stored.
- removeBand emits bandDestroyed(world, band, cause) after the band is spliced out.
- sites.js adds renameSite(world, id, name), because updateSite only merges into data and WP2 has to rename lairs to 'the Bones of X'. node and lair have weight 0 and pinned: true. A newcomer with the lowest score can itself be evicted (literal reading of the contract).
- replayTo has extra options: from (default world.interventions.length; entries with a lower seq are already in the world), sliceMs (default 14), signal ({aborted}), and applyFinal (default true: acts logged on targetDay are applied after the last step, which undo needs). It returns {days, cancelled, ms}. replayStep throws if sim.world !== world.
- Interventions: a logged call nested inside another logged apply is not logged again (world.cache.ivDepth), so a setParam({log:true}) inside a tool does not double-apply on replay. An apply that throws or returns ok:false is still logged, because it may have mutated state. Unknown id, off-map and wrong-entity-kind refusals are not logged. Logged opts are snapshotted before the apply. 'param' entries carry id = key and force: true for non-live params. setParam logs only when the value actually changes, and its log option defaults to false, so existing callers are unchanged.
- ext.js: providers run in provider-id order, not registration order, so results do not depend on import order (this matters for --determinism). registerProvider also bumps extVersion. Extra helpers: mulEachOf (demography), mergeOf (yearRecord), hasProviders, providersOf.
- worldChecksum covers exactly the contract inputs, but mixes 32-bit words with a final avalanche instead of byte-wise FNV-1a, for speed: 0.5 ms vs 1.65 ms on a medium map.
- The keyframe has an extra 'keys' field (world key order). History and chronicle snapshots are generic: arrays are sliced and other values cloned, which covers years/atlas/events/series and any later keys.
- createCiv: when opts.race is omitted, a civ with a parentId inherits the parent's race; an explicit null wins. Added opts.languageStyle, passed to createLanguage.
- damageSettlement scales every fraction (pop, wealth, food, defense, buildings probability) by the 'damage' multiplier; when the multiplier is 1 the code path is unchanged.
- addFigure: 'oldest dead' is taken to mean the figure that has been dead longest (smallest died day; ties go to list order). The just-added figure is never evicted. If no dead, unprotected figure remains, the oldest unprotected figure goes (the previous behaviour). Prophets of living faiths are never evicted.
- createArmy does not pre-create flags.loss, because war.js replaces army.flags right after createArmy. damageArmy creates loss lazily with all 5 sources at 0.
- Chronicle has no 'subject' field: WP3's package text mentions one but contracts §4 does not. Use ref.
- headless --determinism runs the two worlds in child processes (myth excluded with the new --exclude / loadSystems({exclude})), so the module and its providers are never imported in one of them. It honours an explicit --years (default 200).
- SPEC.md §8: the existing UI text is kept under a new heading, 8.3 'The shipped UI', and the expansion summaries are 8.1 and 8.2.

## Kernel notes
- ALL: the zero-behaviour-change check passed. Fingerprints after Wave 0 are atlas 8d8f61fa, kestrel a8a7a74a, north-fen-795 1d7d9865, identical to the baseline. Every ext helper is neutral and allocation-free with no providers. Use listeners(event) from core/hooks.js to skip building an expensive payload when nobody subscribes.
- ALL: providers run in id order. registerProvider(point, id, null) unregisters. A provider that throws is treated as neutral (logged 3 times at most).
- WP3: extVersion() is a process-local counter. NEVER persist it in saved state (for example by folding it into civ.mods._v): --determinism compares saves between a process with the myth module and one without, and fails if you do. Key the mods cache in world.cache instead. Use createCiv({race, languageStyle}); splits inherit race automatically unless you pass race.
- WP4: war.js does `army.flags = {...}` right after createArmy, which drops anything stored earlier. Merge instead (Object.assign) so the flags.loss written by damageArmy survives. Send every casualty through damageArmy(world, army, n, src) with src one of battle | attrition | plague | band | beast.
- WP8: the World tab (worldtab.js) must call setParam(w, k, v, {log: true}) for user changes; the default is not logged. It should also hide params with paramVisible(p, world.params) === false: right now the Myth & Magic sliders show at mythLevel 0. widgets.paramControl has no 'text' type, so worldName renders as a label only until WP5 adds the field. palette should use availableTools(world) and skip t.hidden.
- WP8 keyframes on a medium map at Y300: capture 3.2 ms (fields 1.0, structuredClone 1.7, checksum 0.5), restore 3.5 ms, 8.5 MB of fields per frame. Capture is right at the ≤3 ms budget and will grow by Y1000, so schedule captures off the hot frame (idle callback or between sim slices). Undo: restoreKeyframe(kf, {ui: world.ui}), then sim.setWorld(w2) (runs init), then await replayTo(w2, sim, oldWorld.interventions, oldWorld.time.day, {skip: seq}); applyFinal defaults to true. UI hook subscribers must ignore calls while world.cache.replaying is set; toolApplied is emitted during replay too.
- WP1: setNewsFilter only sees entries that have a key. It may return {imp, fold}; fold: false clears a fold the caller set. getEvents(scale) returns a shared array sorted by id: read it, don't mutate it. Event defs default to family 'misc', cat 'civ', imp 2, cooldownYears 0.
- WP2: addBand computes homeI from x,y unless given; family comes from BAND_KINDS. bandDestroyed fires after removal. Use renameSite for lairs; node and lair kinds are pinned automatically.
- WP5: import mythLevel/mythOn from core/params.js (or core/world.js). The myth stub never draws rng; keep --determinism green (node tools/headless.mjs --determinism, about 25 s on a medium map). Mythic presets carry mode 'mythic'. RACE_META includes label, plural, adjective, color and symbol.
- WP6: merge yearly records with mergeOf('yearRecord', world), which returns {providerId: value} or null. chronicleEntry(world, seq) is a binary search for the 'Because' links. addSite can evict the site it just added if that site scores lowest.
- Tests: set TOOL_DEV.throwOnImpure = true to turn the preview rng-purity check into an exception. The kernel unit tests in scratch/wave0/kernel/tests/*.mjs can be rerun at any time.
- Figures: on atlas, medium, 1000 years at defaults, only 1135 figures are ever created, so the 1500 cap (and with it the fame-aware eviction) never triggers in default histories.

## Registry notes
- Every register* (UI and render) returns an unregister function; registering the same id again replaces the entry. Registration may happen at import or later — consumers read the registries at use time and rebuild on change.
- UI package modules (src/ui/mounts.js list): export mount(app). They are imported in parallel with the renderer before the built-in instruments mount (so tabs registered at import are on the rail from the first paint); mount(app) runs once, before any world exists. A failed import shows in app.loadErrors (HUD warning chip).
- Render plugins register at import time through ./layers.js and must never import ./renderer.js (cycle through plugins.js's top-level await). WP7 lists its own new modules in plugins.js PLUGINS or imports them from renderer.js.
- Layer contract: the renderer sets the slot transform (world slots: entity coords, integer = tile centre, 1 unit = 1 tile; screen slots: CSS px), wraps each draw in save/restore, and switches a layer off after 3 consecutive throws. Push hits as { kind, id, x0, y0, x1, y1, pri } in screen CSS px; built-in pri: storm 1, settlement 2+, army 4. The 'labels' slot pushes candidates shaped like entities.js's ({ pri, text, x, y, angle?, alpha?, alt?, anchor?, st: { size, color, halo, haloW, italic?, sc?, spacing? } }) into env.labels; collisions with already-placed names apply.
- Owners of the hot files must keep the call sites: renderer.js (WP7) the slot('…') calls, env, hits.length = 0, pickAll, terrainStyleFor, the registered-mode branch in _territorySpec and the MODE_IDS fallback in render(); fx.js getFxType/priorityOf/_remember/drawRegistered; modes.js syncRegisteredModes/mapModesFor/registeredStyle/legend default; inspector.js (WP6) registeredView/appendSections/registeredActions/onRegistryChange/teardown; app.js, panel.js, input.js, hud.js, mapdock.js, toasts.js, icons.js, palette.js, main.js (WP8) their registry consults, events and app API.
- Kernel tool API is used only as `import * as kernelTools from '../core/tools.js'` + typeof checks (a named import of a not-yet-existing export is a link error). Current kernel signatures match: previewTool(world, id, x, y, opts), availableTools(world); toolApplied hook (world, payload) is relayed to app event 'toolApplied'.
- WP8: app.follow is { kind, id } | null; select() still clears it (identical to before) and userCamera does not clear it yet — implement 'follow survives selection, cleared by userCamera' yourselves. app.frameSelection(pad) exists but no key is bound (Z is reserved for you). app.fastForward's until test runs after every sim day: keep it O(1); a throwing test is reported and disabled. Pair/entity tools are hidden from the belt until your pair flow / divine-acts sections exist.
- WP6: drawAtlasPlate(canvas, world, snapshot | null, { box: {x0,y0,x1,y1} tiles, marks: [{x, y, kind: battle|razed (cross) | capture (ring) | dot, color?, r?}], scale? }) returns { scale, cx0, cy0, cells, toPx(x, y) }. Registering a view for a built-in kind (tile, settlement, civ, army, war, religion, plague, storm, volcano) only warns — the Inspector draws those itself; edit inspector.js for them.
- Registered views: the Inspector draws the title bar from describe(app, sel) → { name, sub, color } (else label) and icon, plus Show-on-map, Follow (when point/frame exist), registered title actions, Clear; mount(app, sel, el) fills the body only (don't draw your own title). point/frame make selectionPoint, follow and framing work; rendererSel feeds renderer.setSelection (default: tile highlight at point()).
- Registered tabs: mount(app, el) runs once when the tab joins the rail (possibly before a world exists); show() on activation, update() at ≤ 4 Hz while visible, hide() when left; when(app) hides the button; order default 70 (built-ins 10…60); optional flush: true for a full-height pane like the Chronicle.
- Map modes: when(world) is called with world = null on the Genesis screen — handle null. profile.style picks the terrain raster style; territory(r) spec key must change whenever categories/colours change (the renderer prefixes reg:<id>| and appends the terrain static version).
- Toasts: entries with fold: true never toast; .is-watched has no CSS yet (WP8 story.css).
- Pre-existing nondeterminism found while comparing frames: the terrain raster/coast caches sync on version bumps at whatever frame comes next, so during a fast-forward the frame cadence decides the captured state; two runs of one seed can differ by a few dozen coastline pixels. For pixel comparisons (WP7 zoom-perf) force terrain.syncStatic(true), syncBiomes(true), buildAll(), _syncVectors(true) first — with that, old and new frames are pixel-identical.

## Verifier fixes
- src/core/effects.js settlementMods: real determinism bug. The cached monthly aggregate judged an effect live at whatever day the cache happened to fill. A continuous run that filled the cache early in a month kept an effect that expired mid-month, while a world loaded or restored later in the same month (world.cache is emptied) dropped it. That would break save → load → continue and undo/replay hash equality once builders add effects with mid-month `until`. Liveness is now judged at the month's first day, so the value depends only on the effects list, effectsV and the month: an effect counts for the whole month in which it is live, as the comment already promised. Repro and regression test: verify/tests/smods-cache.mjs. Kernel test-effects still passes 30/30. No effect on existing worlds: nothing calls settlementMods yet, and the fingerprints are unchanged.
- SPEC.md §5.1: one sentence added on the settlementMods month semantics.
- src/core/ext.js registerProvider: logs a console.warn when a provider is registered at a point not in EXT_POINTS. A misspelt point (for example 'settlename') used to fail silently; the provider is still registered.
- Rebuilt Atlas of Ages.html and dist/ (bundle.js, artifact/index.html) from the final Wave 0 tree. The registries engineer had deliberately not rebuilt them. I did not republish the claude.ai artifact.
